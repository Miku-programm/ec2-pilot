# API contract for implementation

Same-origin FastAPI backend, cookie session auth. JSON errors `{detail: string}`. All times ISO UTC; UI renders local. No secrets in API responses. API paths start `/api`.

- GET health -> `{ok,version,setup_required}`
- POST setup/login `{password}` -> `{ok:true}` plus HttpOnly session cookie; POST logout.
- GET state -> `{accounts:[],scripts:[],monitors:[],results:[],activity:[],probes:[],meta:{default_region,server_time}}`.
- accounts: `{id,name,aws_account_id,arn,region,access_key_hint,created_at}`. POST accounts `{name,access_key_id,secret_access_key,session_token?,region}` validates with STS; DELETE accounts/{id}; GET accounts/{id}/instances -> `{instances:[]}`.
- instance: `{id,name,state,instance_type,public_ip,private_ip,availability_zone,image_id,launch_time,key_name,security_group_ids:[],subnet_id,elastic_allocation_id?}`.
- GET accounts/{id}/resources -> `{images:[],subnets:[],security_groups:[],key_pairs:[]}` (optional launch helper).
- POST accounts/{id}/instances/launch `{name,image_id,instance_type,subnet_id?,security_group_ids:[],key_name?,user_data?,script_id?,volume_size:8}` -> `{instance_ids:[],message}`. Required `Idempotency-Key` header: 16–64 letters/digits/hyphens; retain the same value for a retry of the same request.
- POST accounts/{id}/instances/{instance_id}/start|stop|reboot `{}` -> `{message}`.
- PUT accounts/{id}/instances/{instance_id}/user-data `{script_id?,user_data?}` -> `{message}`; requires stopped instance. Existing user data update does not guarantee rerun.
- POST accounts/{id}/instances/{instance_id}/rotate-ip `{release_previous:false}` -> `{public_ip,allocation_id,previous_allocation_id?,message}`; manual allocate/associate EIP, old EIP release opt-in and only if owned+safe; IPv4 is billable.
- scripts: `{id,name,content,created_at}`; POST scripts `{name,content}`; PUT/DELETE scripts/{id}.
- monitors: `{id,name,account_id,instance_id,port,interval_seconds,timeout_seconds,samples,enabled,next_run_at,last_status,last_checked_at}`; POST monitors same sans generated fields; PUT/DELETE monitors/{id}; POST monitors/{id}/run -> `{result}` (check only, no automated rotation or failure-streak accumulation). Bounds interval 60..86400, timeout 1..10, samples 1..5. Target is current public IPv4 of selected owned EC2 instance, never arbitrary host input.
- Scheduling: `schedule_type` interval|cron (old missing -> interval; new UI -> cron), `cron_expression` default `*/5 * * * *` exactly five fields, `timezone` default Asia/Shanghai. Optional Linux `app.cron_worker --once` reuses the backend due-task worker; set web `PANEL_SCHEDULER=external` for OS crontab.
- Rotation policy: `auto_rotate:false`, `rotation_trigger` tcp_failure|suspected_filtering, `failure_threshold:3` (1..20), `release_previous:false`. Scheduled checks only; there is no cooldown or daily/rolling-24h attempt cap. Schedule, consecutive-failure threshold and fresh preflight verification determine eligibility for each attempt. Runtime fields `failure_streak`, `failure_ip`, `rotation_status`, `rotation_message`, `last_rotation_at`. Atomic reservation and resource locks are keyed by actual AWS account+region+instance. Errors/interrupted attempts pause rotation until POST monitors/{id}/reset-rotation, returning `{ok,message}`; reset clears the failure streak and preserves operation history. A possibly running interrupted operation must be at least 15 minutes old before reset; this is an in-progress uncertainty guard, not a routine cooldown.
- Saved legacy `cooldown_seconds` and `max_rotations_per_day` settings are removed on migration. Existing operation history remains available.
- Scheduled results optionally have `rotation:{status,message,old_ip?,new_ip?,verification?}`; active statuses skipped,threshold,recovered,rotated,awaiting_review. Verification uses the same observation shape as a check and never recursively triggers replacement. A later scheduled round may rotate again once its consecutive-failure and preflight conditions are met, without an additional delay or attempt-count cap. Historical results may retain the retired cooldown/daily_limit statuses.
- result: `{id,monitor_id,monitor_name,instance_id,target_ip,port,checked_at,status,success_count,samples,latency_ms,loss_percent,gfw_status,summary,observations:[]}`; status reachable/unreachable/no_public_ip/error; gfw_status insufficient_evidence/suspected_filtering/reachable_from_both/unreachable_from_both; no conclusive GFW verdict.
- probes: `{id,name,region_type,url,enabled}`; region_type mainland/overseas; POST probes `{name,region_type,url,token}`; DELETE probes/{id}. POST remote `/probe` accepts `{target_ip,port,timeout_seconds,samples}` with Bearer token (24–512 non-whitespace ASCII characters); samples <=5, timeout <=10, rejects non-public IP. Probe URL must be HTTPS public host, no redirects; root app handles validation.
- activity: `{id,action,message,created_at,level}`.

UI Chinese dark polished dashboard with accounts, EC2 list/actions, script library, TCP monitor/history, probe settings. Add-account must not call contact API. UI confirmations for instance mutations and visible EIP cost/restart/user-data caveats; prevent duplicate clicks. Any demo is explicitly labeled, isolated, read-only and never calls mutation APIs.
